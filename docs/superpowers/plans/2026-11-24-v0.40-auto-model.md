# v0.40 Task 13: Choose model automatically

Goal: a per-agent setting lets simple turns run on the provider's small model, so that Claude and
ChatGPT usage goes down. The setting is off by default. Off, or absent on an old agent, gives
exactly today's `turn/start` model and effort.

## Facts found in the code

- The turn model comes from `ThreadLifecycle.turnSettings` (`thread-lifecycle.ts`). It is sent on
  every `turn/start` by `DrainScheduler.startDelivery`. The Slack reply profile uses the same
  mechanism: it replaces the model and the effort for the turn only (`SLACK_REPLY_MODEL`,
  `SLACK_REPLY_EFFORT = "low"`).
- The small model of each provider is the v0.39 "cheaper default":
  `agentProviderDescriptor(provider).defaultModel`. Claude: `claude-sonnet-5-5` (the same model
  as the Slack reply). Codex: `gpt-6-luna`. No other per-provider small model exists.
- The provider model list is `ProviderRuntime.listModels()`. No user setting turns off a single
  model (searched contracts, backend, main, `packages/ui` for hidden, disabled, turned-off models).
  The only exclusion is `DrainHooks.servesModel` (a removed OpenCode endpoint). The guard checks
  both.
- Claude: `#openTurn` in `claude-client.ts` calls `query.setModel()` on the open session when the
  turn names another model. The session, the thread and the workspace stay. Codex: `turn/start`
  carries `model` and `effort` per turn on the same thread. Thread start and resume still use the
  agent's own model.
- Cost of a switch: the prompt cache is per model and holds the system prompt, the tool schemas and
  the history. The first turn on another model reads all of it without cache. While the own model's
  cache is warm, a switch can cost more than it saves. (Not measured; from the provider cache rules.)
  Handling: the warmth rule (rows 12 and 13) below. The cache stays warm about 5 minutes after a turn
  (`CACHE_WARM_MS`).
- The model list starts as the static `FALLBACK_MODELS`, and a failed `model/list` keeps the old
  list. `ProviderRuntime.hasListedCatalog(provider)` is true only when the provider's CLI listed the
  current models and its last read did not fail.
- Agent settings are JSON in `projection_agents.agent_json`. Messages are JSON in
  `projection_thread_messages.message_json`. No migration is needed.
- The Team API projects agents and messages through frozen field lists, so new optional fields do
  not go on the wire. The setting is local-only, like `weeklyTokenBudget`. A remote update that
  names it is refused with `error.agent.tokenSettingsLocalOnly`.

## Storage

- `AgentSummary.autoModel?: boolean`. Absent means off. Stored only as `true`; `false` removes it.
- `UpdateAgentInput.autoModel?: boolean`. Validated in contracts, `agent-store.ts` and
  `src/main/ipc/agent-inputs.ts`. Copied on duplicate.
- `ConversationMessage.autoModelName?: string`: the display name of the model GoAhead chose,
  set on the assistant messages of a turn only when the turn model differs from the agent's model.

## Rule table (`src/backend/agent/auto-model.ts`)

First row that matches wins. "Own" = the agent's model and effort, exactly as today.

| # | Condition | Result |
| --- | --- | --- |
| 1 | Setting off or absent | own |
| 2 | Provider is not Claude or Codex | own |
| 3 | A thread profile already set the model (Slack reply context) | profile model (unchanged) |
| 4 | Channel task or external messaging thread (relay) | own |
| 5 | Any message in the batch is from a teammate or a routine | own |
| 6 | Any attachment | own |
| 7 | Text longer than 280 characters, or more than 3 lines | own |
| 8 | Code or work words: a code fence or backtick, a path or URL, or a word such as code, fix, bug, debug, build, implement, refactor, deploy, test, plan, analyse, review, write, create, research, compare, file, script, error | own |
| 9 | Agent's own model is not a larger model (see below), or is a long-context variant (`[...]`) | own |
| 10 | The provider's CLI did not list the current catalogue (fallback list, or the last read failed) | own (fallback) |
| 11 | Small model is not in the provider list, or `servesModel` refuses it | own (fallback) |
| 12 | The last accepted turn on this provider thread ran on another model than the small one and ended less than `CACHE_WARM_MS` (5 min) ago | own (its cache is warm; stops the flip-flop) |
| 13 | Otherwise: a short chat message from the person, and either the last turn ran on the small model less than 5 min ago (its cache is warm), or there is no turn yet in this run, or the last turn ended 5 min or more ago (both caches cold) | small model, effort `low` (or the model's default effort if it does not list `low`) |

The last turn is recorded only after `turn/start` is accepted (model, start time), and its end time
on `turn/completed`. It is in memory only: after a restart the cache counts as cold, which is true
because the provider process restarted. One clock (`AgentServiceOptions.now`) serves the tests.

Larger models: Claude families `opus` and `fable`; Codex ids with `terra`, `sol` or `astra`.
An unknown model is not larger, so it keeps its own model. An agent already on the small model
keeps its own model and effort.

Tool hints: no cheap source exists before the turn. The work words of row 8 stand in for them.

## Changes

1. Contracts: the two optional fields, the validators, `agentAutoModelEnabled`,
   `providerSupportsAutoModel`.
2. Backend: `auto-model.ts` (pure rule), `DrainScheduler` applies it after `turnSettings`, records
   the turn model in `#turnModels` and `requestedModel`, and registers the label.
   `ConversationRuntime` keeps the last accepted turn per provider thread (model, end time) and the
   model of a start in flight (for usage on `turn/started`), and stamps `autoModelName` on the
   turn's answer.
3. Main: input decoding and the remote refusal.
4. UI: a switch in `AgentSettingsPanel` (shared UI, props only) under the token settings. For a
   provider without support, the switch is off and disabled and the text says so. A small label in
   the message header in `ChatMessageRow` when `autoModelName` is set. en keys only.
5. Preview mock: `updateAgent` handles `autoModel`.
6. Release note `changelog.d/auto-model.md`.
