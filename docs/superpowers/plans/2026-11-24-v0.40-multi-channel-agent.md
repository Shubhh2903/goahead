## What upstream 862cf3873 changes

About 100 lines. It is a small delta on an upstream scheduler that already has these parts:

- `DrainScheduler` lanes: `interface Lane { agentId; taskId }`, `#lanesOf`, `#drainingLanes`,
  `laneKey`, `laneChannelId`. Each agent has one lane for the own chat, one for each task, and one
  for each channel (`refs/upstream/openbot-main-2026-11:src/backend/agent/drain-scheduler.ts`, 1532 lines).
- Mailbox lanes: `MailboxStore.channelLanes(agentId)`, `laneActive(agentId, taskId)`, a queue head
  for each lane (upstream `src/backend/mailbox-store.ts:1000`, `:1098`).
- A task system: `#tasks.openTaskIds`, `#tasks.limit` (the "Parallel threads per agent" limit),
  `#tasks.oneTurnAtATime` (provider `concurrentTurns: false`).
- Earlier upstream work (#4761): a channel turn already runs beside the agent's own chat, and the
  work of other agents does not hold it.

The commit only raises the limit "one channel turn for each agent" to "`channelTurnLimit` channel
turns for each agent" (`agentTaskLimit` less running tasks, at least 1), keeps one turn for each
channel, renames `ChannelStore.agentAssignment` to `agentWork` (returns all rows), and gives the
`busy` hook a `channelId`.

## Why upstream thinks it is safe

Each channel turn runs on its own provider thread: the execution thread of (channel, agent),
`channels.store.context(channelId, agentId).threadId`. The agent's own chat uses `agent.threadId`.
So two channel turns never share a provider thread, and the own chat is not touched. Each lane has
its own queue head and its own drain, so a reply is routed by the assignment of its delivery. A
provider that cannot run two turns at once (`concurrentTurns: false`) keeps strict serial order.

## How GoAhead differs (why a port is a redesign)

GoAhead has the provider-thread part (execution threads per channel and agent exist:
`ConversationRuntime.registerExecutionThread`, `#executionSnapshots`). It has none of the
scheduling parts. Checked with `grep -rln "laneActive|channelLanes|lanesOf|oneTurnAtATime|concurrentTurns|taskLimit" src/backend packages/contracts/src`: no match.

1. `DrainScheduler` is keyed by agent, not by lane: `#drainingAgents`, `#scheduledDrains`,
   `#drainTasks`, `#slotWaiters`, `#turnModels` are all `Map/Set<agentId>`. `drainAgent` returns
   when `workingSnapshot(agentId)?.activeTurnId` is set. `mayDrain` is false while any turn of the
   agent runs (`src/backend/agent/drain-scheduler.ts:151`, `:257`).
2. The mailbox has one queue head for each agent: `MailboxStore.nextQueued(agentId)`
   (`src/backend/mailbox-store.ts:869`), `startingDeliveryForAgent(agentId)` (`:983`).
3. `ConversationRuntime.workingSnapshot(agentId)` returns one snapshot with an active turn
   (`src/backend/agent/conversation-runtime.ts:428`). Stop (`agent-interrupt-tool.ts:75`),
   `TurnLifecycle` (`turn-lifecycle.ts:335`) and `DrainScheduler.modelForTurn` assume one turn
   for each agent.
4. GoAhead's channel model is host-wide, not per agent. One active assignment reserves the whole
   host: `ChannelService.mayDrain` holds normal work of every agent while any assignment is active
   (`src/backend/channel-service.ts:867-871`, `queueHold` doc at `:887-897`). The pump also skips
   when any normal delivery of any agent is unresolved (`normalBusy` hook,
   `src/backend/agent-service.ts:762`, used at `channel-service.ts:727`). Upstream removed the
   host-wide reservation long before this commit.
5. No task system, so there is no `agentTaskLimit` to share. A limit would need a new agent
   setting (and maybe a migration, which the controller ruling forbids).

To let one agent run two channel turns at once, GoAhead first needs: per-lane drain state in
`DrainScheduler`, per-lane queue heads in `MailboxStore`, per-thread active turns in
`ConversationRuntime` and `TurnLifecycle` (Stop, lost-turn recovery, steer, `modelForTurn`),
removal of the host-wide channel reservation, and a limit source. That is the upstream
lane redesign, not this commit.

## Options for the controller

A. Drop Task 9 from v0.40 (recommended), or record it as a later epic "port upstream drain lanes".
B. Approve a redesign as its own task: lanes in DrainScheduler and MailboxStore, per-thread turns

C. Smaller step: remove only the host-wide reservation, so two *different* agents run channel
