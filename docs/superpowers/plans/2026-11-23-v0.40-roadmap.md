# GoAhead v0.40.0 Roadmap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> This is a roadmap over 17 independent features. Before a feature starts, write its own detailed task plan
> (`docs/superpowers/plans/2026-MM-DD-v0.40-<feature>.md`, superpowers:writing-plans format) against the code of
> that day. The roadmap fixes scope, order, interfaces between features, gates and tests; the feature plan fixes
> files and signatures.

**Goal:** Ship GoAhead v0.40.0 with 10 features ported from upstream OpenBot and 7 GoAhead features: better
organisation and speed in the UI, more capable agents, lower Claude/ChatGPT usage, and better phone use.

**Architecture:** Each upstream feature is ported by hand from `refs/upstream/openbot-main-2026-11` (fetched
2026-11-23, tip `aafb9aa5b`; no merge base with GoAhead), in Promise style, English only. Each feature lands in its
own worktree and branch, is merged to `master` by the user after its checks, and the release is cut once from
`master` after the upgrade-safety audit.

**Tech Stack:** Electron 44 + SolidJS renderer, `@openbot/ui`, Node SQLite (`openbot.db`), Team API v6 with
capability strings, Expo 57 mobile app, Cloudflare Worker (account), Signal (Render).

**Spec:** The feature list agreed in the session of 2026-11-23 (items 1–17 below). Upstream sources are the
commits named per item.

## Global Constraints

- English only: add `en` i18n keys only; every user string comes from `@openbot/i18n` keys (desktop, web, mobile).
- No `effect` dependency; port upstream Effect code to Promise style.
- Migrations are irreversible: next free version is **38**. Each migration needs preservation fixtures for every
  released schema (8–37), failure/rollback/retry, downgrade, missing-version, foreign-key and integrity tests, and
  `LATEST_SCHEMA_SQL` + `openbot-database-schema-history.json` in the same change.
- Released Team API adapters are frozen (v1–v6). New wire behaviour = a new GoAhead capability string in
  `packages/contracts/src/team-protocol/current.ts` + its own frozen `*-v1.ts` file. Never copy upstream
  protocol v7–v10 files.
- Desktop features that a remote host does not offer must be hidden behind the capability (older host = no UI).
- Checks per AGENTS.md: one test file at a time (`bun run test:desktop -- <path> --maxWorkers=1`), Biome on
  changed files, narrow typechecks only (`typecheck:node`, `typecheck:renderer`, one package). The user commits
  and pushes; never `git commit`/`git push` for the user.
- Release notes per feature in `changelog.d/<branch>.md`; mobile notes in `apps/mobile/changelog.d/<branch>.md`.
- Shared UI goes in `packages/ui` (props only, no `window.openbot`); read `packages/ui/AGENTS.md` first.

## Review Focus

1. **A phone or desktop on an older version** talks to a v0.40 host (or the reverse): new folders, threads,
   multi-select answers and connection status must degrade to today's behaviour, never error. Owner: items 1, 3,
   8, 15 — each feature plan adds a test with the capability absent.
2. **Existing data after the upgrade**: chats without a folder, routines without a template, agents without a
   model-routing setting must look and work exactly as in v0.39. Owner: items 1, 12, 14 (default-value tests).
3. **Usage numbers that are wrong** (double count, missing providers, resumed sessions) would undo the trust the
   dashboard is for. Owner: item 11 — tests over real `usage` rows with resumed sessions and two providers.
4. **Automatic model choice picks a model the provider does not list** or one the user turned off. Owner: item
   12 — fallback test to the agent's own model.
5. **Parallel tasks that never return** (agent stopped, provider exits) leave the caller waiting forever.
   Owner: item 6 — timeout/stop test that the caller gets a failed result.

## Phase 1 — Quick wins

### Task 1: "Recent activity" chat sort (item 4) — S

- Scope: add `recent-activity` to the sort options; sort by last message or run time; persist the choice as the
  existing sort setting does. Mobile list too.
- Tests: sort function over chats with/without activity; the setting round-trip.
- [ ] Feature plan → implement → tests → `changelog.d/sort-recent-activity.md` (+ mobile note)

### Task 2: Keyboard shortcut settings and Open Agent shortcut (item 2) — M
- Upstream: `4b860db5a` (#14167), `6a5f3fab5` (#12036; mobile part = iPhone Shortcuts).
- Scope: settings page to view/rebind shortcuts, conflict detection, new shortcuts; mobile "Open Agent" App Intent.

- Tests: rebinding conflict rules; shortcut persistence; one E2E smoke that a rebound shortcut opens the target.
- [ ] Feature plan → implement → tests → notes

### Task 3: Run-condition templates (item 14, GoAhead) — S
- Scope: in `AgentRoutinesSettings.tsx`, a "Use a template" menu that fills `conditionCommand` + `conditionWhen`:
  new git commit (`git log -1 --format=%H`, output-changes), new file in a folder (`ls -t <folder> | head -1`,
  output-changes), web page changed (`curl -fsSL <url> | shasum`, output-changes), file exists
  (`test -f <path>`, exit-zero). Templates with a placeholder ask for the folder/URL/path. Same templates in
  the `create_routine` tool description.
- Tests: template fills the draft; placeholder substitution quotes paths safely (spaces, quotes).
- [ ] Feature plan → implement → tests → notes

### Task 4: Claude steer while a tool runs, and Stop for a lost Claude turn (item 7) — S–M

- Risk: these touch the same text-buffer/turn code as v0.39's text preview — re-run `claude-client.test.ts` in full.
- Tests: upstream tests ported; plus preview cleared on Stop.
- [ ] Feature plan → implement → tests → notes

### Task 5: Multi-select questions on all providers, answered on the phone (item 8) — M

## Phase 3 — Agent power

### Task 9: Parallel tasks with returned results, one agent in several channels (item 6) — L
- Upstream: `740efbb4d` (#13577), `862cf3873` (#14215). Backend only.
- Risk: queue and mailbox ordering; caller waiting forever (Review Focus 5).
- Tests: two tasks run at once and both results reach the caller; a stopped task returns a failed result; an
  agent serves two channels without crossing replies.
- [ ] Feature plan → implement → tests → notes

### Task 10: "Update all" providers, automatic CLI updates, "Restart now" (item 9) — M
- Upstream: `4bc9404ab` (#13496), `dc52f0ba6` (#13917).
- Risk: GoAhead pins runtimes in `native-runtime.lock.json`; automatic updates must stay within managed (pinned)
  versions — do not auto-download unpinned CLIs. Restart must still wait for idle agents by default.
- Tests: update-all runs each outdated provider once; a failure on one does not stop the others; Restart now
  skips the idle wait only when asked.
- [ ] Feature plan → implement → tests → notes

## Phase 4 — Usage (GoAhead)

### Task 11: Usage dashboard per agent (item 11) — M
- Scope: a Usage page (desktop; local host first): tokens per day per agent and provider for 7/30 days, cached
  vs uncached input, top agents, routine runs skipped by run conditions (count of cancelled runs with the
  run-condition reason), agents over their weekly budget. Data: existing `usage` table (`database/usage*`), no
  migration. Remote hosts: only if a capability exists; otherwise local only.
- Tests: aggregation over resumed sessions and two providers (Review Focus 3); skipped-run count; empty state.
- Produces: `usageByAgent(range): AgentUsageSummary[]` in the backend, reused by Tasks 12 and 13 to show savings.
- [ ] Feature plan → implement → tests → notes

### Task 12: Cheaper hand-offs between agents (item 13) — M
- Scope: `send_message` to a teammate carries a short brief instead of the caller's context; the reply comes
  back without a second full turn where possible (token idea 3). Measure with Task 11.
- Tests: hand-off payload size bound; reply reaches the caller once; no loss of attachments.
- [ ] Feature plan → implement → tests → notes

### Task 13: Automatic model choice per turn (item 12) — L
- Scope: per-agent setting "Choose model automatically" (off by default for existing agents): a cheap rule
  (message length, tools needed, routine vs chat, attachments) picks the small or the agent's own model for the
  turn; Claude uses `turnSettings` (as Slack reply contexts do), Codex the turn model. Shows the chosen model on
  the message.
- Risk: provider does not list the chosen model (Review Focus 4) → fall back to the agent's model.
- Tests: rule table; fallback; setting off = today's behaviour.
- [ ] Feature plan → implement → tests → notes
