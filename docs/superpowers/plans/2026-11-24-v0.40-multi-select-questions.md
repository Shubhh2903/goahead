# Multi-select questions (v0.40, Task 5)

Port of upstream 8d94d815e (#14213). Upstream flag name: `multiSelect`.

## Wire decision
- Answers already carry `string[]` per question: no answer wire change.
- The question needs an optional `multiSelect: true`. Frozen v1-v6 question codecs drop it and stay unchanged (`v6.ts`, `v6-base.ts` and the older files).
- Follow the `plan` / `senderMember` / `quiet` precedent: the flag rides beside the frozen projection
  in the current v6 adapters, edited additively (`v6-adapter.ts`, `v6-base-adapter.ts`; helper in `question-multi-select-v6.ts`), as `quiet` does. No new capability: an older phone drops
  the key and shows a normal single-choice question (one tap sends one option, or typed text).
- Present non-`true` value is a protocol error (fail closed).

## Steps
1. contracts: `multiSelect?: boolean` on `AgentPromptQuestion` + validator; `withQuestionMultiSelect`; wire in
   `v6-base-adapter.ts` (events) and `v6-adapter.ts` (conversation HTTP).
2. backend: `ask_user` tool field; `promptQuestions` keeps the flag; Claude `AskUserQuestion` passes it.
3. mobile: `togglePick`/`picked`/`answerText` in `use-question-prompt.ts`; toggle buttons + Done in
   `chat-question-prompt.tsx`; typed reply sends picked options too.
4. tests: decode with the flag, older-client path (frozen projection drops it), mobile answer encode.
5. notes: `changelog.d/multi-select-questions.md`, `apps/mobile/changelog.d/multi-select-questions.md`.
6. desktop: port the multi-select part of upstream 9491b02ab to `QuestionPromptBubble` and `Questionnaire.Choice`
   (checkboxes, Submit answer, picks in option order plus typed text). Story and test added.
Gap: channel prompts show a multi-select question as single choice.
