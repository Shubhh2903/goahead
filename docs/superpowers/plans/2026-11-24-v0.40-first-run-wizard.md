# v0.40 first-run setup wizard (Task 16)

## What the existing flow covers

- `OnboardingFlow` (shown by `AppView` while `AppSetupState.completed` is false): provider sign-in
  ("meet"), the computer-use step, sounds, and the jobs step. "Open GoAhead" calls `saveSetup`.
  Main writes `setup.json` in the profile's userData (`src/main/setup-store.ts`). That file is the
  only "done" state. There is no skip: a provider must be connected.
- First agent: after setup, a profile with no agents opens the existing `FirstAgentSetup` form in
  the conversation pane (`agents-context.applyStoredAgents`). It cannot be cancelled. The model is
  resolved from the saved provider (`resolveCreationModel`): Claude gives `claude-sonnet-5-5`
  (`agent-providers.ts`), and the backend gives it the catalog effort `medium`
  (`newAgentEffort`). ChatGPT gives `gpt-6-luna` with effort `low`.
- Slack and Gmail: only in Server settings > Connectors (`ConnectorsPanel`).
- Phone QR: only in App settings > Mobile connect (`SettingsMobileConnectTab`).

## What the wizard adds

One flow, four steps: `provider` -> `agent` -> `connect` -> `phone`.

1. `provider` is the existing `OnboardingFlow`. New: a "Skip" on the provider step (continue
   without a connected provider) and "Skip setup" on every step (save setup and end the wizard).
2. `agent` is the existing `FirstAgentSetup` form. New: a "Skip for now" button in first-run mode.
   A skip closes the form and stops its auto-open for the rest of the session.
3. `connect` is a new dialog that shows the existing `ConnectorsPanel` with only Slack and Gmail.
   The connector flows are unchanged. The Slack controller moves up in `WorkspaceOverlays` so that
   Server settings and the wizard share one instance.
4. `phone` shows the existing `SettingsMobileConnectTab` with its own store.

Each step has Skip; the dialog steps also have Back, Next/Finish and "Skip setup".

## Done rule (no migration, no new IPC)

The wizard starts only when the setup state that loaded at launch is not completed. The existing
`setup.json` is the persisted state, the same as for the old onboarding:

- Finish or skip of step 1 writes `setup.json`. After a restart the setup is completed, so the
  wizard never starts again.
- An existing user has `setup.json` (old onboarding done), so the wizard never starts.
- A profile with agents but no valid `setup.json` sees the old provider step (existing behavior).
  At the `agent` step, a roster that loads with agents ends the wizard at once (treated as done).
- The `connect` and `phone` steps are held in memory. A restart in the middle ends the wizard.
