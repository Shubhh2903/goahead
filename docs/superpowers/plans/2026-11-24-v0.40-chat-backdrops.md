# v0.40 Task 8: chat backdrops, video backdrop, avatar shapes

Upstream: `bd623ab8c` (#10503), `b4644ea2b` (#14211), `04be9f03b` (#14274). Port by hand.

## Scope

In scope:

- Five built-in animated scenes (pond, jellyfish, sunset, snowfall, fireflies) behind the whole
  window. Desktop is dark only, so the scenes paint their dark look.
- An uploaded image (PNG, JPEG, GIF, WebP, AVIF; 20 MB or less) or video (MP4, WebM; 100 MB or
  less) as the backdrop. At most 12 uploads; the oldest one that does not show is removed first.
- A "Backdrop" row in Settings > General > Appearance: None, the scenes, the uploads, Upload,
  Remove.
- Reduced motion: a scene shows one still frame; a video does not play. A hidden window stops the
  scene and pauses the video.
- Avatar shapes ghost (`fantome`), jellyfish (`meduse`) and octopus (`poulpe`), with the bloub bump
  0.4.1 -> 0.7.0 (MIT).

Out of scope (reported):

- The agent `set_backdrop` tool and HTML-page backdrops. They need the upstream chat-visual page
  extensions, the preview page store, the agent event bridge and the Undo notice (more than 500
  lines). The core backdrop works without them.
- The chat background color (upstream `chat-background.ts`, `ChatBackgroundSetting`). GoAhead does
  not have it.
- Mobile appearance setting. GoAhead mobile has no appearance settings screen.
- Translations (en keys only).

## Storage decision

Upstream keeps uploads in renderer IndexedDB and the choice in `localStorage`. GoAhead keeps both
in main, under Electron `userData`, so a release upgrade keeps them and main enforces the limits.

- Choice: `<userData>/openbot-chat-backdrop-v1.json` = `{ "version": 1, "choice": <scene> |
  "custom:<uuid>" | null }`. A missing, unreadable or unknown-version file reads as `null`: today's
  look.
- Uploads: `<userData>/chat-backdrops/<uuid>.<ext>` plus the index
  `<userData>/chat-backdrops/backdrops-v1.json` = `{ "version": 1, "backdrops": [{ id, name, kind,
  mimeType, extension, createdAt }] }`. A bad index reads as empty; the files stay on disk.
- No database migration.

## IPC (new group `backdrops`)

| Endpoint | Payload | Result |
| --- | --- | --- |
| `backdrops:get-state` | none | `ChatBackdropState` (`choice`, `uploads`) |
| `backdrops:set-choice` | `ChatBackdropChoice \| null` | `ChatBackdropState` |
| `backdrops:upload` | none | `ChatBackdropUploadResult` (`added` / `cancelled` / `refused`) |
| `backdrops:remove` | upload id | `ChatBackdropState` |

- The renderer never sends a path or bytes. Main opens the file dialog, checks the extension
  allowlist, the size (before and after the copy) and the file signature, then copies the file.
- `define-ipc-group` checks the sender before each payload is decoded, as for every group.
- The file is served by the new privileged scheme `openbot-backdrop://file/<uuid>`, only for an id
  in the index. CSP adds `openbot-backdrop:` to `img-src` and `media-src` only.
