## 2. Automatic updates (main, pinned only)

GoAhead differs from upstream: a manual update installs the latest upstream release, but an
automatic update must stay on `native-runtime.lock.json`.

- `ProviderRuntimeManager`: after each check (start, then each hour), start a download of the
  **pinned** spec for each provider where:
  - update checks run (`startUpdateChecks` was called),
  - the managed copy is installed (`ready`, or `not-downloaded` with a previous version),
  - its version is older than the pinned version (never a downgrade of a newer manual update),
  - no system CLI is in use for it, and no configured CLI path,
  - the user did not cancel that pinned version in this session (in memory).
- The pinned spec comes from `runtimeSpec(runtime, target, lock)`. It never reads `#latest`.
- A failed automatic download stays in `download-error`; it is not started again by itself.
- The download goes through `updateRuntime`, so it waits for idle agents as a manual update does.
- `getStatus` hides the offer only when the automatic update will install that same version.
- Remove nothing else. No provider-off state exists in GoAhead main.

## 3. "Restart now"

- `IdleRestart.restartNow()`: refuse while restarting or installing; no-op without a waiting
  restart; else skip the readiness check and run the same restart steps.
- IPC `update.restartNow` = `"update:restart-now"`: contract, handler (`handler(...)`, sender check by
  the group), preload decoder, preview mock.
- Renderer: `updates-port`, `updates-context`, `SettingsModal`, `WorkspaceOverlays`.
- Shared UI: `updates-store` `restartNowOffered`/`restartNow`; `SettingsUpdatesTab` button and
  `ConfirmDialog` ("Keep waiting" is the cancel).
- i18n (en only): `update.idleRestart.restartNow`, `restartNowTitle`, `restartNowDescription`,
  `keepWaiting`.
